# Learned patterns

- `.agents` and `.codex` are protected paths in current Codex workspace-write sandboxes. Mutable project memory belongs under `docs/agent-memory/`.
- Cache entries must not contain the absolute Romero root. Use a stable managed-area identifier plus a path relative to that area.
- Equal SHA-1 values across games represent independent required file copies, not a shared physical library entry.
- Unknown directories are quarantined as whole entries and left unprocessed in work. Collision suffixes append to directory names but precede a regular file's final extension.
- A source filename is never authoritative during promotion. DAT filenames are authoritative; the source-to-target assignment is determined from the complete hash multiset and, for CUE games, validated by the rewritten CUE hash.
- `serde-saphyr` can deserialize an unquoted numeric scalar into `String`; set `Options::no_schema = true` and use an explicit string-to-`PathBuf` deserializer when configuration requires actual YAML strings.
- Resolve and inspect every managed path first, load and validate every DAT next, and create missing managed directories only after both stages succeed. This preserves the no-mutation guarantee for invalid catalog sets.
- Treat SQLite as a rebuildable index over the authoritative filesystem. Route every cache mutation through one global 60-second scheduler instead of assigning durability rules by operation type. Keep mutations immediately visible in the transaction, checkpoint only at safe points, commit the remaining batch after full success, and let the next run repair a rolled-back batch.
- A cache timing policy should measure from the first dirty mutation, reset only after a successful commit, and use an injected monotonic clock for deterministic unit tests. Emit typed periodic/final commit progress only after the corresponding operation succeeds.
- Emit typed cache-hit events but keep them and per-file promotion mechanics hidden by default. `--verbose` is additive presentation filtering in the CLI, not an engine behavior switch.
- Render hashing progress as `Hashing <path>` without a byte-count suffix; the path is sufficient operational feedback.
- A whole-game content multiset must be unique across all selected systems, not merely inside one DAT, because a work multiset otherwise cannot be assigned conservatively to a destination system.
- Send live progress to stderr and retain the deterministic final summary on stdout so users can redirect either stream independently.
- Audit the authoritative library once, scan work once, and incrementally update a path/basename/content-indexed work inventory after every successful operation. Keep only complete game identifiers for the library; reports and diagnostics should consume runtime state instead of forcing a final verification scan.
- Derive library-copy source paths from a DAT reverse content index filtered by the complete-game set. This avoids retaining library member records, lets newly promoted games become sources immediately, and preserves deterministic source selection by sorting managed DAT paths case-insensitively.
- Build recognition as one fixed priority queue seeded only by non-CUE content. Candidate count is calculated once from incomplete games, and claimed or moved seeds are skipped later; do not restart matching or rebuild global candidates after promotion.
- Cache parsed CUE bytes/documents by unchanged work key. Inventory changes require reevaluation against current filenames and hashes, not rereading or reparsing the CUE.
- Keep the checked-in `romero.yaml` example minimal and directly usable: list only the three supported relative path settings with their default values.
- Preserve Romero's project origin in user-facing documentation with a personal, conversational voice: it is the user-friendly Rust successor to the author's long-used but unfinished personal C++ ROM manager.
- Use the conventional term DAT in user-facing documentation; reserve format-specific terminology for implementation documentation where the distinction matters.
- Until automated release workflows exist, document Git-based Cargo installation as the available path and describe prebuilt CI release binaries only as planned work.
- Qualify ZIP support wherever it appears in user documentation: Romero reads DAT archives only and does not currently process compressed ROM sets.
- Present normal Romero use as a repeatable loop rather than a one-time setup: configure or create paths, add DATs and ROMs, run, inspect incomplete work/output, and repeat after every catalog or ROM update.
- Refer to Romero's managed root uniformly as `ROOT` in user-facing prose, commands, configuration paths, and directory diagrams.
- Describe work filename collisions as automatically incremented numeric suffixes without tying the user-facing explanation to specific example filenames.
- Describe hashing in its actual run order: DAT loading and cache opening precede the cache-backed library audit and work inventory, and content matching starts only after those inventories are ready.
- State the user-facing safety guarantee at the ROM-payload boundary: library content is moved back to work rather than deleted, while a work CUE may be removed after its validated replacement is written and generated `.miss`/cache state may be rewritten.
- Treat CUEs as supporting evidence, never as recognition seeds. Read them once before content mutations, index valid documents by total `FILE` directive count, and search only the bucket matching the selected game's non-CUE DAT entry count. Count repeated `FILE` directives separately and ignore `TRACK` count.
- Preserve exact-CUE precedence: accept an exact-name size/SHA-1 match without a FILE-count constraint; otherwise try a valid same-count rewrite of that exact-name sheet before other same-count sheets in deterministic filename order.
- Keep complete-game work duplicates untouched, but report them after normal promotions. Use work-only multiset and CUE validation, reserve selected physical files across deterministic duplicate blocks, retain typed details for library consumers, and never let duplicate diagnostics mutate work.
- Emit incomplete diagnostics at the point a content-queue winner is selected. Retain the typed details in `ExecutionSummary` for consumers but omit them from its final `Display`, preventing delayed or duplicate CLI output.
- In content matching, a complete candidate always beats an incomplete one. Complete ties use case-insensitive system/game order; incomplete candidates score selected work, verified library content, and a valid CUE before the same tie-breaker. Claim selected work, displayed mismatches, and the selected CUE only after choosing the one winner.
- Render incomplete details game-first with one case-insensitively sorted row for every expected DAT ROM. Render exact or renamed work content as `OK`, content available from a verified complete library game as `LIBRARY`, absent entries as `MISSING`, and exact filenames with wrong size or SHA-1 as `MISMATCH`; show filenames relative to work rather than root-relative `work/...` paths.
- Keep ordinary summary/detail `Display` deterministic and free of terminal escapes. Pass an explicitly colored incomplete-detail wrapper through `anstream` on stderr so terminals receive styling while pipes, redirects, Windows consoles, and standard no-color environment conventions are handled centrally.
- Route every user-visible or behavior-selecting name/path order through one case-insensitive comparator. Compare locale-independent Unicode lowercase forms first and original spelling second; this keeps `.miss` files, diagnostics, scan order, assignment, library source choice, and progress deterministic without ASCII uppercase unexpectedly sorting before lowercase.
- Select the newest DAT by its original header identity before converting the header into a cross-platform managed system name. Sanitize only headers, never DAT ROM filenames; reject case-insensitive post-sanitization collisions before mutation so distinct catalogs cannot silently share a library directory.
- Treat XML element content as a sequence of text-bearing events. With quick-xml, entity references split surrounding text into separate `Text` and `GeneralRef` events, so replacing a field on each `Text` event truncates names after escapes. Disable per-fragment trimming, accumulate `Text`, `GeneralRef`, and CDATA, resolve XML entities explicitly, and trim only the completed field.
- Emit the always-visible `MatchingContent` event before CUE indexing and queue processing. Immediate diagnostics then inherit clear console context without embedding internal-stage metadata into every `LeftoverDetail` or making the distinction depend on verbose mode.
- With quick-xml 0.41, pass the XML version explicitly for attribute normalization and use the version-specific content helpers. Romero preserves its existing XML 1.0 behavior with `XmlVersion::Implicit1_0` and `xml10_content`.
- With sha1 0.11, digest output no longer implements lowercase-hex formatting. Encode the finalized bytes explicitly to retain forty-character lowercase SHA-1 strings.
- Construct serde-saphyr 0.0.29 deserialization options with `serde_saphyr::options!`; direct `Options` field construction is deprecated ahead of 1.0.
- Keep Romero's tests source-adjacent and unit-only. Disable Cargo integration-test auto-discovery, run `cargo test --lib`, and use only inline data with in-memory collaborators; do not invoke public OS-backed entry points or the CLI from tests.
- Route configuration inspection and DAT discovery through the same internal filesystem abstraction used by the engine. This preserves production behavior while letting each module exercise path kinds, validation ordering, direct readers, and ZIP bytes independently with `MemoryFileSystem`.
- SQLite unit tests must use `Connection::open_in_memory()` with `temp_store=MEMORY`; share schema and transaction initialization with production while leaving file-backed locking and OS behavior outside the unit-test boundary.
