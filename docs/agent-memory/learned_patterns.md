# Learned patterns

- `.agents` and `.codex` are protected paths in current Codex workspace-write sandboxes. Mutable project memory belongs under `docs/agent-memory/`.
- Cache entries must not contain the absolute Romero root. Use a stable managed-area identifier plus a path relative to that area.
- Equal SHA-1 values across games represent independent required file copies, not a shared physical library entry.
- Unknown directories are quarantined as whole entries and left unprocessed in work. Collision suffixes append to directory names but precede a regular file's final extension.
- A source filename is never authoritative during promotion. DAT filenames are authoritative; the source-to-target assignment is determined from the complete hash multiset and, for CUE games, validated by the rewritten CUE hash.
- CI formatting is verification-only: use `cargo fmt --all --check`, never a rewriting formatter invocation.
- `serde-saphyr` can deserialize an unquoted numeric scalar into `String`; set `Options::no_schema = true` and use an explicit string-to-`PathBuf` deserializer when configuration requires actual YAML strings.
- Resolve and inspect every managed path first, load and validate every DAT next, and create missing managed directories only after both stages succeed. This preserves the no-mutation guarantee for invalid catalog sets.
- Hash-cache durability is per file, not per scan or successful run. After calculating and storing one SHA-1, commit it before scanning the next file and immediately begin a new exclusive transaction. Emit a typed hash-save event after the commit; the CLI renders it only under `--verbose`. Checkpoint cache path updates after successful moves, copies, and deletions as well, so interruption does not strand a saved hash under its former path.
- Emit typed cache-hit events but keep them and per-file promotion mechanics hidden by default. `--verbose` is additive presentation filtering in the CLI, not an engine behavior switch.
- Render hashing progress as `Hashing <path>` without a byte-count suffix; the path is sufficient operational feedback.
- A whole-game content multiset must be unique across all selected systems, not merely inside one DAT, because a work multiset otherwise cannot be assigned conservatively to a destination system.
- Validate release publication by comparing the draft’s complete asset-name set with the five expected target ZIPs before changing the release from draft to published.
- Do not trust a transitive crate to enforce its actual MSRV when its manifest omits `rust-version`. Test Romero's locked dependency graph with the declared Rust 1.85 toolchain; `libsqlite3-sys` 0.38.1 compiled only on newer Rust because its bundled build script used `cfg_select!`.
- `serde-saphyr` also omitted an effective MSRV: 1.0.0-rc.1 used let chains and `is_multiple_of`, both unavailable in Rust 1.85. Version 0.0.10 retains the required `Options::no_schema` behavior without those newer language/library features.
- Send live progress to stderr and retain the deterministic final summary on stdout so users can redirect either stream independently.
- Reconciliation rescans managed directories after immediate promotions. Gate per-file hash/cache progress through the same first-seen cache-accounting set so each path is reported once instead of once per internal scan.
- Keep the checked-in `romero.yaml` example minimal and directly usable: list only the three supported relative path settings with their default values.
- CUE recognition is sequential, not a global candidate-selection problem. Iterate CUEs in deterministic work order and immediately apply the first complete DAT match after resolving references and validating the rewritten CUE hash. Do not compare valid candidates, reject overlaps, or wait to batch promotions.
- Build leftover diagnostics game-first with sorted `(system, game)` groups and one row for every expected DAT ROM. Assign each physical non-CUE work file only to its largest content- or exact-filename candidate group, measuring size by distinct work files before assignment and breaking ties alphabetically by system/game. Within the selected group, prioritize exact content filenames, then deterministically assign renamed content matches. Render exact or renamed content as `OK`, absent entries as `MISSING`, and assigned exact filenames with wrong size or SHA-1 as `MISMATCH`; show filenames relative to work rather than root-relative `work/...` paths.
- Keep the library summary's ordinary `Display` deterministic and free of terminal escapes. Expose an explicitly colored display wrapper, then pass it through `anstream` in the CLI so terminals receive styling while pipes, redirects, Windows consoles, and standard no-color environment conventions are handled centrally.
- Route every user-visible or behavior-selecting name/path order through one case-insensitive comparator. Compare locale-independent Unicode lowercase forms first and original spelling second; this keeps `.miss` files, diagnostics, scan order, assignment, recovery, and progress deterministic without ASCII uppercase unexpectedly sorting before lowercase.
